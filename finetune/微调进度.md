## 二、最终结果速览（同口径，本机真实 MySQL）

| 配置 | L1 可执行率 | L2 执行准确率 EX | L3 澄清/拒答 |
| --- | --- | --- | --- |
| 基线：现有流水线 + deepseek-flash | 98.9% | 81.7% | 0.0% |
| 基线：Qwen3-8B 原版 | 84.9% | 61.3% | **77.3%** |
| **交付：Qwen3-8B LoRA 1 epoch** | **93.5%** | **79.6%** | 59.1% |
| 对照：LoRA 2 epoch | 91.4% | 76.3% | 54.5% |
| 对照：LoRA 3 epoch | 92.5% | 76.3% | 54.5% |

**结论**：
- ✅ EX **+18.3**、可执行率 **+8.6** —— 微调核心目标达成；
- ✅ **1 epoch 最优**（2/3 epoch 的 eval_loss 更低，但 EX 反而掉了 3.3 个点）；
- ❌ 澄清能力从 72.2% 掉到 55.6%，且训得越久安全拒答越差（4/4 → 1/4）。

## 四、评测设计说明（为什么数字可信）

1. **只变一个变量**：A/B1/B2/B3 四组使用**完全相同的检索上下文与 system 提示词**，
   唯一差异是模型权重。做法是预测时**跳过两个 LLM 过滤节点**（见 `dump_context.py`）。
2. **口径差异已标注**：deepseek 基线是**带过滤**跑的，不与 Qwen3 各行逐位对比。
3. **结果集等价**而非 SQL 文本比对 —— 同一问题有多条等价 SQL，文本比对会误判。
4. **评测器修正过 L3 打分**：初版关键词表把措辞不同但语义正确的拒绝判成失败；
   已扩充等价说法并新增"伪拒绝"检测（嘴上拒绝、正文贴 SQL 代码块仍算失败）。
   修正后基线 L3 由 59.1% → **77.3%**，四组统一重算，**L1/L2 不受影响**。

## 六、已知缺口 / 风险

- **澄清能力是当前最大短板**，根因已定位（训练数据缺"带 schema 的模糊短问"），
  属于明确可修的问题，见上文 P0。
- **危险拒答不稳**：3 epoch 的模型在"删除 fact_order 表"上输出过 `DELETE FROM fact_order;`。
  **上线前必须做安全兜底**（SQL 只读校验），不能只依赖模型。
- **训练时用了 `qwen3` 模板（含思维链），而训练答案是纯 SQL**。
  预测脚本已做兼容（`enable_thinking=False` + 剥离思维链）；
  若后续 L2 异常，可换 `qwen3_nothink` 模板重训对比。
- **数据库 `dim_date` 只覆盖 2025 Q1**，超范围时间类问题会查空，
  评测集与语料生成时已避开。
- **本地训练损失未留存**：三组的 `train_loss` 没下载回来，文档只记录 eval_loss。
  下次训练结束请把 `trainer_state.json` 一并下载，便于画损失曲线。
