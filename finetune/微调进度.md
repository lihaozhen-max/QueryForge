## 评测设计说明

预测时**跳过两个 LLM 过滤节点**，直接使用召回结果作为 schema 上下文。原因：

- 快 60 倍（3 小时 → 3 分钟）
- 更重要：过滤节点有时会裁掉 JOIN 需要的维表，会导致"模型答错"与
  "过滤裁错"两个变量混在一起。跳过后 base 与 LoRA 使用**完全相同的上下文**，
  唯一变量只剩模型本身。

代价是 schema 略长，绝对 EX 可能比线上真实表现略低；但该影响对两边对称，
不影响对比结论。本机基线（deepseek）是带过滤跑的，口径略有差异，已在矩阵中标注。

## 已知缺口

- **澄清样本 33 条偏少**：反向变换要求源 SQL 含可摘除的时间/分组要素，
  而 SQL 池有限。缓解：澄清是可泛化行为，配到 50–100 条即可起效；
  训练后看 L3 指标验证是否奏效，不足则可从真实提问日志补充。
- **训练时用了 `qwen3` 模板（含思维链）**，而训练答案是纯 SQL。
  预测脚本已做兼容（`enable_thinking=False` + 解析时剥离思维链）。
  若 L2 指标异常低，可考虑用 `qwen3_nothink` 模板重训一次对比。
- 数据库 `dim_date` 只覆盖 2025 Q1，超范围时间类问题会查空，生成模板已避开。
