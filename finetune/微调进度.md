## 三、下一步：P6 工程侧补澄清（不需要 GPU）

**不要再训模型解决澄清。** 实测证据：两轮数据专门优化过，L3 从原版的 77.3%
一路降到 50.0%。而原版模型本身有 72.2% 的澄清能力 ——
**它本来就会反问，是微调把它压掉了。**

要做的是在 LangGraph 里加一个**确定性前置判断节点**（纯规则，不调模型）：

```
用户问题
   ↓
【新增】信息充分性判断
   ├─ 有明确时间范围？  没有 → 反问"统计哪个时间段？"
   ├─ 有明确指标？      没有 → 反问"看哪个指标？"
   └─ 有明确分组维度？  没有 → 反问"按什么维度看？"
   ↓ 三项齐全
generate_sql（换成微调后的 v2 模型）
```

好处：准确率 100%（逻辑确定）、可解释、可单元测试、零 GPU 成本。
而且这正好补上 deepseek 基线 L3 = 0.0% 的那个空白。

## 四、评测设计说明（为什么数字可信）

1. **只变一个变量**：A/B/B′ 使用**完全相同的检索上下文与 system 提示词**，
   唯一差异是模型权重与训练数据。做法是预测时**跳过两个 LLM 过滤节点**。
2. **口径差异已标注**：deepseek 基线是**带过滤**跑的，不与其余各行逐位对比。
3. **结果集等价**而非 SQL 文本比对 —— 同一问题有多条等价 SQL，文本比对会误判。
4. **评测噪声已实测**：同一原版模型跑两次，三层指标差异 ≤ 1 条
   （115 条中 13 条输出文字不同但判定全同）。所以 ≥2 条的差异可当真实变化。
5. **评测器修正过两处**：L3 拒答词表过窄 + 新增伪拒绝检测；
   训练样本与评测集查重（挡掉一处真实泄漏）。两处均只影响 L3。

## 六、已知缺口 / 风险

- **澄清是当前最大短板（L3 50.0%）**，且已证明**靠训模型解决不了**。
  改由 P6 的工程侧前置判断兜底。
